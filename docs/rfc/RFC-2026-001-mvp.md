## 2. Tech Stack

### 2.1 Frontend

| Component | Technology | Rationale |
|-----------|------------|-----------|
| Runtime | Node.js + pnpm | Fast iteration |
| Framework | React 19 | Easy to hire for |
| Build | Vite 6 | Fast HMR, ESM-first |
| Editor | Tiptap | Correct abstraction for editor-driven AI UX |
| State | TanStack Query | Server state; reduces custom caching |
| Styles | Inline (MVP) | No design system yet |

### 2.2 Backend

| Component | Technology | Rationale |
|-----------|------------|-----------|
| Framework | NestJS 11 | Structured, testable |
| API | GraphQL + REST | GraphQL for data, REST for streaming |
| Database | PostgreSQL + pgvector | Single datastore, simpler ops |
| Cache/Queue | Redis + BullMQ | Background jobs core to product |
| Auth | Magic-link (JWT) + Sessions | Secure, no password management |
| CSRF | csrf-csrf | Double Submit Cookie pattern |
| Encryption | Node crypto (AES-256-GCM) | No additional deps |

## 5. Security Design

### 5.1 Authentication Flow

```
User email → POST /auth/magic-link
    → Generate 15-min JWT (one-time use)
    → Send magic link via Resend
    → User clicks link → JWT validated
    → Session created (express-session + Redis)
    → Secure cookie set
```

### 5.2 Session Security

| Setting | Value |
|---------|-------|
| Cookie name | `__Host-assistai_sid` (prod) / `assistai_sid` (dev) |
| `HttpOnly` | `true` |
| `Secure` | `true` (prod) / `false` (dev) |
| `SameSite` | `Lax` |
| `maxAge` | 8 hours rolling (28800000ms) |

### 5.3 CSRF Protection

- Pattern: Double Submit Cookie + HMAC
- Package: `csrf-csrf` (NOT `csurf` - deprecated + CVE)
- Exempt: GET, HEAD, OPTIONS, pre-auth endpoints
- Header: `x-csrf-token`

### 5.4 Credential Encryption

- Algorithm: AES-256-GCM
- Format: `iv:authTag:ciphertext` (hex)
- Key: `CREDENTIAL_ENCRYPTION_KEY` env var
- Use case: Google OAuth tokens stored encrypted

### 5.5 SSRF Protection

- Validate URLs against allowed IPs
- Block RFC 1918 + reserved ranges
- Custom lookup fn on HTTP agent
- Reuse validated IPs on actual request

## 6. Completion Pipeline

### 6.1 Request Flow

```
User types in editor
    → Debounce (300ms)
    → POST /completions/stream (SSE)
        → Get CSRF token
        → Validate session
        → Check rate limits
```

### 6.2 Retrieval-Augmented Generation

```
1. Get editor context (text before cursor)
2. Retrieve top-4 chunks (cosine similarity ≥ 0.72)
3. Assemble prompt: system prompt + context + retrieved chunks + user text
4. Call LLM (OpenRouter or BYO endpoint)
5. Stream response via SSE
6. Log completion + retrieval hits for analytics
```

### 6.3 Prompt Structure

```
[System prompt - Spanish legal drafting]
[Retrieved chunks with source citations]
---
[User text up to cursor]
```

## 7. Indexing Pipeline

### 7.1 Flow

```
File selected in Drive picker
    → Job queued (BullMQ)
    → Parse: PDF/DOCX/TXT → plain text
    → Chunk: 1500 chars, 200 overlap
    → Embed: text-embedding-3-small (1024 dims)
    → Index: pgvector HNSW
    → Update document status
```

### 7.2 Chunking Parameters

| Parameter | Value |
|-----------|-------|
| Library | `RecursiveCharacterTextSplitter` |
| Chunk size | 1500 chars |
| Overlap | 200 chars |
| Separators | `["\n\n", "\n", ". ", ";\n", "; ", ", ", " "]` |

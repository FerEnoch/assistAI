# Google OAuth Config Specification

## Purpose

Define el contrato del scope OAuth de Google Drive que debe usar `DriveOAuthService` para permitir que el picker liste archivos existentes del usuario.

---

## Requirements

### Requirement: REQ-6 — OAuth scope MUST be `drive.readonly`

`DriveOAuthService.SCOPES` MUST include `https://www.googleapis.com/auth/drive.readonly` and MUST NOT include `https://www.googleapis.com/auth/drive.file`. This change is necessary so the picker can list all files in the user's Drive, not only files created by this application.

#### Scenario 6.1: OAuth flow initiated with correct scope

- GIVEN a user initiates Google Drive OAuth
- WHEN the authorization URL is generated by `DriveOAuthService`
- THEN the `scope` parameter MUST include `drive.readonly`
- AND MUST NOT include `drive.file`

#### Scenario 6.2: Existing tokens with `drive.file` scope

- GIVEN a user has a stored token obtained with the old `drive.file` scope
- WHEN the user attempts to list files via `GET /sources/:id/files`
- THEN the request MAY fail with a 403 insufficient scope error
- AND the system MUST treat this as a `needs_reauth` state (marking source accordingly)

#### Scenario 6.3: Google Cloud Console scope registration

- GIVEN the OAuth consent screen in Google Cloud Console does NOT list `drive.readonly`
- WHEN any user attempts the OAuth flow
- THEN Google MUST reject the authorization request
- AND this is a deployment pre-condition that MUST be verified before release
